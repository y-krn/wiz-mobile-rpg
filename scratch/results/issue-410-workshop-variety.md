# Issue #410 工房バリエーション測定・採用結果

測定日: 2026-08-04 JST。割合の区間は Wilson 95% CI。`N<30` のセルは未確定で、採用根拠に使わない。

## 結論

- `pools` に6ノードを追加する。`convenience` と `classes` は今回追加しない。
- 追加対象は、実発動を caller 経路で観測でき、実発動機会数 `N>=30` の6 core。
- これは純粋な新コンテンツ追加ではなく、変更前は無料抽選だった6 coreを工房購入へ移す「既存coreの有料化」。`empty` / `stats` / `gear` は合計32.9%のrunで、変更前より使えるcore poolが少ない。
- cost=7採用根拠は掃引の順位/kneeではない。cost 5〜10では主指標に検出可能な単調効果がなく、既存 `pool_blood_wand` の呪布5＋黒角2（合計7）へ揃える設計一貫性で7を採用する。
- 新構成は16ノード、40購入step、総需要161素材。run開始時の買い切り率は13.3% [11.4%,15.3%; N=1200]。
- 主指標の点推定差は冒頭で明示する。同条件 origin/main → 採用版で、平均到達 B2.98 → B2.81、素材EV/時間 0.1212 → 0.1173、素材入手 49.30 → 44.97/run、bank 25.20 → 22.29/runへ低下。改善は工房買い切り率 25.3% → 13.3%のみで、これはシンク追加の直接効果。before側の平均/EVは同じ集計のCIを取得していないため、有意差とは主張しない。
- 採用版 `workshop-complete` の終了時core 0個は79.9% [77.3%,82.3%]。同一 depth env の origin/main はcore装備22.7%（0個77.3% [74.6%,79.8%]）で、点推定は+2.6pt悪化だがWilson CIは重なる。8割がcore未装備という構造は変更前から大きく、#271/#409/#411の前提を更新する。
