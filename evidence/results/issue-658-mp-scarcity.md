# Issue #658: MP は資源として実在するか

## 判定

基準シナリオ `workshop-empty` では、MP は全職共通の run 資源ではないが、
僧侶の戦闘・回復局面では実在する制約だった。

- 僧侶は、実体の `getSpellPayment` が支払い不能を返したイベントを B20 までに
  戦闘 335 回、回復 161 回観測した。B20 の 125 run 中、MP 支払い不能を伴う
  終端戦闘は 11 run、死亡かつ同じ終端指標を持つ run は 11 run だった。
  （後者は無限 MP 反実仮想ではなく、測定上の因果代理指標である。）
- 魔術師は B20 の終了 MP が p25/p50/p75 = 100.0/100.0/100.0% で、
  121/125 run が死亡終了しても MP 中央値は 100% だった。MP 支払い不能は
  戦闘 43 イベント、終端指標は 1/125 run に留まった。
- Fighter / Thief はこの sim の呪文候補がなく、MP 0% で終了する。これは
  MP 枯渇ではなく、MP を使う行動が存在しないことの結果である。
- したがって結論は「MP が枯れて行動が止まっている」側だが、職業限定である。
  僧侶の深度 B2–B5 以降の戦闘・回復では MP 制約が観測され、魔術師では
  主に MP が余ったまま HP 枯渇で終了する。MP 系のコスト・供給調整を全職に
  対して無効と結論する根拠は得られなかった。将来の調整対象を僧侶の
  戦闘／回復へ限定できるかは、ポリシー影響を分離した追加測定が必要である。

終了理由の大半は死亡であり、MP が残っている死亡も多い。よって「MP が
  一度でも不足した」ことを「死亡原因」と同一視してはいない。`causeEnd` は、
  死亡 run の終端戦闘で実体の支払い不能を観測した数であり、MP 無限の
  反実仮想を行った因果効果ではない。

## 測定方法とポリシー分離

MP の可否判定は sim に式を複製せず、次の実体経路を通して観測した。

- 戦闘の呪文候補: 既存の `chooseSimulationAutoCombatAction` を、候補発見の
  ためだけに `canCastSpell: () => true` で probe する。probe が選んだ呪文へ
  `getSpellPayment(character, spell.cost)` を実際に呼び、返却値を記録する。
  実行側の支払い可否は既存 `getSpellActionPayment` を通す。
- 回復: 既存回復候補の各呪文について `getSpellPayment` を呼び、可なら既存の
  MP 消費・効果適用を行う。MP 不足時は候補を止めている。
- 探索: `castExplorationSpell` から `getSpellPayment` を呼ぶ。
- `mpBlocked` は source の返却値が `canCast: false` だったイベント数であり、
  `character.mp - cost` の再計算ではない。`mpInsufficient` は source が
  MP 不足を検出したイベント（血杖の HP fallback を含む）、`policyBlocked` は
  sim 側の選択制限を分離した値である。
- 僧侶の B20 基準ケースの戦闘では `mpBlocked=335`、`policyBlocked=498`、
  そのうち `reserveBlocked=163`。つまり 163 件は DIOS 用 MP 予約のための
  sim ポリシーであり、335 件は source 支払い不能である。回復は
  `mpBlocked=161` が全て source 支払い不能だった。
- `SIM_EXPLORE_SPELLS` は今回指定していないため既定値 off。探索の候補は全職・
  全深度で 0 件だった。従って探索中に MP が不足しないという結論は出せず、
  「探索呪文を使わないポリシーによって観測機会が無い」と報告する。
- 血杖 scenario では `mpInsufficient` と `mpBlocked` を分けた。MP 不足でも
  HP fallback が通る場合は `mpInsufficient` のみ増え、HP も払えない場合に
  `mpBlocked` が増える。基準 `workshop-empty` には血杖はない。

## 3. HP 枯渇との比較

基準 B20 の終了理由は、Fighter 121/125、Thief 113/125、Priest 120/125、
Mage 121/125 が死亡だった。死亡時 HP は全 run で 0% だが、同じ死亡集合の
MP p25/p50/p75 はそれぞれ Fighter `0/0/0%`、Thief `0/0/0%`、Priest
`6.7/80.0/100.0%`、Mage `100/100/100%` だった。

したがって、魔術師は HP が先に尽き、MP を余らせている。僧侶は HP 死亡が
大勢を占める一方、MP 0–低残量で死亡する一部の run に加え、戦闘と回復の
支払い不能イベントが継続している。撤退時は HP 低下が主因で、MP は多くの
run で 0%だが、撤退標本は B20 でも 2–12 件と小さいため MP 制約の判定には
使っていない。

## ポリシー由来の人工物と未判定点

- `getSpellActionPayment` の DIOS 予約 1 MP は、実体の支払い不能とは別に
  `reserveBlocked` として記録した。これを MP 枯渇と数え上げていない。
- 探索呪文は `SIM_EXPLORE_SPELLS=on` を指定しない限り発火しない。今回の
  指定条件では探索 phase を資源テストできず、探索中の MP 制約の有無は判定
  できない。
- 戦闘 probe は既存 selector の「本来選びたい呪文」を観測するためのもので、
  `canCastSpell` の override で実際の cast を強制していない。実行側は既存
  payment gate と source の `getSpellPayment` を使用している。
- `mpDepletionCausedEndRuns` は terminal combat と死亡の同時観測であり、
  MP を無限にした反実仮想との差ではない。MP が HP より先に尽きたことの
  厳密な因果寄与や、MP 不足が戦闘勝率を何ポイント変えたかは未判定である。
- 僧侶の MP 不足イベントの一部は、回復候補を試して止まったもの、戦闘では
  候補呪文が source で払えなかったものを表す。パーティ全体の行動停止時間や
  「別の安い呪文へ切り替えた場合」の反実仮想までは測っていない。
