# Issue #507 盲目バランス測定

## 結論

B案（戦闘終了時の盲目解除）を採用する。勝利または逃走で生存している味方の盲目を解除し、全滅時には解除しない。攻撃の50%ミスと被ダメージ半減、宝箱解除時の盲目補正は維持する。

A案（被ダメージ半減だけを除去）は改善するが、B案より endpoint が低い。C案（標準kitの回復薬1個を目薬へ交換）は目薬の使用を増やすが、回復薬との競合で成績を悪化させる。A/Cは採用しない。

## 測定条件

- seed=507、Fighter/Thief/Priest/Mage 各3,000 run、合計12,000 run。
- 6工房の重みは `30/74/69/216/47/764`。各工房の calibration は1,000 run。
- `SIM_PARALLEL` は未指定。実行時の available/resolved parallelism は15/15、map cacheは1024。
- mapは `generateSharedRunFloor` を使い、タスク間で同一生成結果を共有した。
- 固定条件は #461/#485 を継承し、`TRAP_POLICY=conservative`、`TRAP_AVOIDANCE_POLICY=ev`、
  `STATUS_CURE_POLICY=smart`、`FLEE_POLICY=ev`、`IDENTIFICATION_POLICY=powder`、
  `ELITE_POLICY=avoid`、ポーション/状態異常商人補給なし。標準kitは
  `TOWN_PORTAL, HEAL_POTION×4, ANTIDOTE, GUARD_POTION`。
- 平均値は normal 95% CI、率は Wilson 95% CI。N<30のセルは未確定扱いとした。

再現コマンド（各variantを個別に実行）:

```sh
for variant in baseline a-miss-only b-battle-end c-kit; do
  SIM_VARIANT="$variant" SIM_RUNS=3000 SIM_CALIBRATION_RUNS=1000 \
    node scratch/simulations/sim_issue_507_blind_balance.js
done
```

baseline/Cは盲目の現行挙動（基準ソース `origin/main`=`9a8a5fc780242ada612b6f4686bff03b97cea0ca`）で測定した。Aは同じ基準から攻撃の被ダメージ半減だけを一時的に除去した比較条件。Bは実ソース変更後に再測定し、最終 `src/combat_logic/round.js` のSHA-256は `2d466cfa9a83f6813c87551235d3e650de31294e3476ecff16dc8ee44abf33d9`、測定runner `scratch/simulations/sim_issue_507_blind_balance.js` は `11c3f66c8694ce1519b04890d2ea723fcfd1ab36e4f8340b1cee55f669ac750e`。

## C案のkit競合

両kitとも7枠。baselineは回復薬4個、Cは回復薬3個+目薬1個。出発材料の総量は、帰還の翼の任意8個を含めて baseline 20、C 19。Cは `獣の牙−1 / 硬い皮−1 / 霊粉+1` だが、材料が安くなることより回復薬1個を失うことの影響が大きい。標準kitへ目薬を必須化しない。

## 宝箱解除と他の対策

`src/rules/trap_rules.js` の盲目時宝箱解除補正 `blind ? chance / 2 : chance` は維持する。これは戦闘終了回復とは別の対策であり、解除率だけを単独目標にしない。今後も `chestDisarmAttempts` と `kit` / `direct` / `forced` 経路を併記する。
