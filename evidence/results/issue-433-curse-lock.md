# Issue #433: 呪いロックと装備選択方針の上限測定

Closes #433

## 結論

src/ は変更していない。呪い率・呪い検知率・装備選択方針の balance 値も採用していない。

固定深度の天井測定は、PR #430 と同じ水準に合わせて N=500、calibration N=100 で取り直した。4条件の「呪いなし」は、呪い生成を止める生成オフである。これはコア遭遇率まで変え、呪いロック単独の反実仮想ではない。そこで、呪いの生成・付与を現行のままにして装備判断のロック gate だけを切るロックのみオフを追加した。

生成オフでは粉=2の B5死亡率が現行 49.4% [43.2,55.6] から 67.4% [61.5,72.8] に動いたが、ロックのみオフでは 52.1% [46.0,58.2] だった。無制限粉でも現行 47.5% [41.6,53.6]、生成オフ 59.2% [53.3,64.8]、ロックのみオフ 47.3% [41.5,53.2] で、生成オフの悪化はロックのみオフでは再現しない。したがって、現時点で最も整合する説明は生成側の変更と乱数消費順を混ぜた測定側の問題であり、呪いが生還に寄与するという因果結論ではない。

4条件の天井は CI が重なり、どの軸が採用可能な knee かを決める結果ではない。呪い率と score 許容幅の sweep も非単調で、単発値を knee と呼ばない。検知率はゲーム側に装備判断へ渡る経路がなく、結果同一は「効果なし」ではなく「sim未再現」である。

## 機構の切り分け：生成オフとロックのみオフ

生成オフは、生成側の呪い抽選を止めるため pickCurseEffectId を呼ばない。現行の N=500 でも、コア生成数 / そのうち cursed は次のように変わった。

| 条件 | 粉 | コア生成数 / cursed |
| --- | --- | --- |
| 現行 | 2 | 350 / 83 |
| 生成オフ | 2 | 279 / 0 |
| ロックのみオフ | 2 | 362 / 96 |
| 現行 | 無制限 | 399 / 92 |
| 生成オフ | 無制限 | 308 / 0 |
| ロックのみオフ | 無制限 | 338 / 95 |

生成オフはアイテム列と、その後の乱数消費を変える。ロックのみオフは生成・付与を有効にしたまま、scratch の equipGreedyUpgrades にある現装備の curse lock gate だけを無効化する。選択結果が変われば後続の深度・経路は変わるので、総生成数が現行と完全一致することを要求する条件ではないが、生成側を消した条件ではない。

## 検知率経路の監査

ゲーム側の事実は次の通り。

- src/systems/equipment_generation.js は生成時に curseSuspected を作り、src/rules/item_rules.js は未鑑定品の表示文言（呪いの疑いあり / 兆候なし）へ使う
- src/equip.js の canEquip は現装備の isCurseLocked だけを確認し、curseSuspected を装備可否・装備候補の判断へ使わない
- powder の scratch sim の equipGreedyUpgrades も curseSuspected を判断へ渡していなかった

したがって、ゲームにも「呪いの疑いを見て装備を控える」という選択経路は現状ない。現状プレイヤーが呪いを回避する手段は、鑑定で実体を確認してから装備する経路に限られる。このため検知率軸は本 issue では未回答であり、curseSuspected を装備判断へ渡す経路を追加する別 issue の候補とする。今回その経路を仮実装して検知率の結論を作ることはしない。
